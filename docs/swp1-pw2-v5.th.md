ตัวอย่าง SWP1-PW2-V5 หนึ่งเครื่องได้รับการแปลงเมื่อ 2026-10-18 หลังจาก Tuya-Convert แบบปกติล้มเหลวด้วยตัวระบุ PSK `02` การตรวจสอบผ่านสายพบ ESP8266EX คริสตัล 26 MHz และแฟลช 2 MiB สำเนาสำรองจากโรงงานที่ตรวจสอบแล้วให้ผัง GPIO ก่อนเขียนเฟิร์มแวร์สุดท้าย ต่อมาเจ้าของยืนยันว่าทำงานเป็นเต้ารับข้างชั้นหนังสือได้ตามปกติ

หลักฐานนี้ใช้กับตัวอย่างเครื่องนี้ ไม่ใช่ผลิตภัณฑ์ทุกตัวที่มีตัวเรือนคล้ายกัน สวิตช์เก่าที่ไหม้ซึ่งใช้เทียบฮาร์ดแวร์เป็นอีกเครื่องหนึ่ง โดยยังเก็บข้อมูลระบุตัวตนใน Home Assistant และการตั้งค่า LocalTuya ของเครื่องนั้นไว้

## ฮาร์ดแวร์ที่ยืนยันแล้ว

- รีเลย์: **GPIO13 ทำงานเมื่อระดับสูง** โหมดคืนค่า `ALWAYS_OFF`
- ปุ่มจริง: **GPIO3 / RXD0 ทำงานเมื่อระดับต่ำ** ใช้พูลอัปและกรองการเด้ง 30 ms
- ไฟรีเลย์: **GPIO14 ทำงานเมื่อระดับต่ำ** ตามสถานะที่สั่งให้รีเลย์ทำงาน
- ไฟการเชื่อมต่อ: **GPIO0 ทำงานเมื่อระดับต่ำ**
- บันทึกอนุกรม: ปิดใช้งาน ถอดสาย UART ของเครื่องโปรแกรมก่อนทดสอบปุ่ม เพราะอินพุตใช้ RXD0 ร่วมกัน

JSON ฮาร์ดแวร์ของแอปจากโรงงานระบุหน้าที่เหล่านี้ และการสังเกตปุ่ม รีเลย์ และไฟในภายหลังสอดคล้องกัน ไม่ต้องไล่ทดสอบเอาต์พุต GPIO หรือใช้เฟิร์มแวร์วินิจฉัยกลาง โปรไฟล์นี้ไม่ได้ตั้งค่าการวัดทางไฟฟ้า LED หรือสถานะ API ไม่ใช่ข้อมูลป้อนกลับจากหน้าสัมผัสรีเลย์

## การต่อสายแรงดันต่ำ

**ถอดอุปกรณ์ออกจากไฟบ้านโดยสมบูรณ์ก่อนเปิดหรือเชื่อมต่อสิ่งใด และคงการตัดไฟบ้านไว้ตลอดการโปรแกรม** ใช้แหล่งจ่ายควบคุมแรงดัน 3.3 V และลอจิก UART 3.3 V ที่ตรวจสอบแล้ว ตัวแปลงระดับใช้ปรับสัญญาณ ไม่ใช่แหล่งจ่ายควบคุมแรงดันให้อุปกรณ์

![การต่ออนุกรมตามหน้าที่: แหล่งจ่ายภายนอก 3.3 V อะแดปเตอร์ UART 5 V ตัวแปลงระดับ และ TYWE3S](images/swp1-serial-wiring.svg)

ภาพแสดงการเชื่อมต่อทางไฟฟ้า **ไม่ใช่ตำแหน่งแผ่นบัดกรีจริง** ระบุขาโดยใช้ [เอกสารข้อมูล Tuya TYWE3S](https://developer.tuya.com/en/docs/iot/wifie3smodule?id=K9605ua1cx9tv) และเทียบทิศทางรูปกับบอร์ด อย่าเดาหน้าที่จุดทดสอบของบอร์ดหลักจากตำแหน่ง แรงดันจ่ายพิกัดตามเอกสารคือ 3.3 V

สำหรับอะแดปเตอร์ลอจิก 5 V ที่ใช้ครั้งนี้:

1. **5V ของอะแดปเตอร์ → จุดอ้างอิง HV** ของตัวแปลง
2. แหล่งจ่ายควบคุมภายนอก **3.3V → VCC ของโมดูลและ LV ของตัวแปลง**
3. GND อะแดปเตอร์ GND ตัวแปลง ขั้วลบแหล่งจ่าย และ GND โมดูลต้องใช้กราวด์ร่วมกัน
4. **TX อะแดปเตอร์ → HV1** และคู่ **LV1 → RXD0 ของโมดูล**
5. **TXD0 โมดูล → LV2** และคู่ **HV2 → RX ของอะแดปเตอร์**
6. ปล่อยเอาต์พุต 3V3 ของอะแดปเตอร์ไว้โดยไม่ต่อ ห้ามต่อเอาต์พุตแหล่งจ่ายสองชุดขนานกัน

ใช้ตัวแปลงที่รองรับความเร็วและทิศทาง UART ชุดนี้ทำงานที่ 115200 baud หลังแก้สาย แต่ไม่ได้รับรองบอร์ด HV/LV ราคาถูกทุกแบบ อะแดปเตอร์ UART 3.3 V จริงสามารถไม่ใช้ตัวแปลงได้หลังตรวจสอบระดับเอาต์พุต

อะแดปเตอร์วัดได้ 3.3 V เมื่อไม่มีโหลด แต่อุปกรณ์ที่ต่ออยู่ได้รับเพียง **1.9 V** และ TX ยังให้ **5.1 V** ทั้งสองเป็นคนละปัญหา แหล่งจ่ายภายนอกแก้ VCC ส่วนตัวแปลงปรับระดับ UART วัด VCC ที่โมดูลขณะมีโหลดและวัดสัญญาณอ้างอิงกราวด์เดียวกัน ดู [คู่มือการเชื่อมต่อจริงของ ESPHome](https://esphome.io/guides/physical_device_connection/)

## โหมดดาวน์โหลด สำรองข้อมูล และเฟิร์มแวร์

ขณะปิดไฟ ให้ **GPIO0 ต่อกับ GND** จ่ายไฟแรงดันต่ำกลับ แล้ว **ต่อ RST กับ GND ชั่วครู่และปล่อย RST** คง EN เป็นระดับสูง และอย่าค้าง RST เป็นระดับต่ำ GPIO0 อาจต่อกราวด์ระหว่างเขียนได้ แต่ต้องถอดจัมเปอร์ก่อนบูตปกติ ข้อความ ROM ที่อ่านได้ `boot mode:(1,0)` ยืนยันโหมดดาวน์โหลด ดู [เอกสารโหมดบูตของ Espressif](https://docs.espressif.com/projects/esptool/en/latest/esp8266/advanced-topics/boot-mode-selection.html)

มีได้เพียงโปรแกรมเดียวที่ครอบครองพอร์ตอนุกรม ออกจาก Miniterm ก่อนใช้ esptool การไขว้ TX/RX ให้ถูกแก้ปัญหาการสื่อสารสุดท้ายได้ LED ติดไม่ได้พิสูจน์ว่าลิงก์อนุกรมทำงาน

ก่อนเขียน ผู้ปฏิบัติงานอ่านแฟลชโรงงาน **ครบทั้ง 2,097,152 ไบต์** และใช้ esptool ตรวจสำเนาเทียบกับอุปกรณ์ เก็บสำเนา บันทึกอนุกรมดิบ อิมเมจที่สร้าง และข้อมูลรับรองไว้นอก Git สาธารณะ เพราะดัมป์โรงงานอาจมีความลับสำหรับการจัดเตรียม [เอกสารคำสั่ง esptool](https://docs.espressif.com/projects/esptool/en/latest/esp8266/esptool/basic-commands.html) อธิบายการระบุอุปกรณ์ `read-flash`, `verify-flash` และ `write-flash` เลือกขนาดการอ่านจากแฟลชที่ตรวจพบจริง ไม่ใช่ชื่อบนตัวเรือน

สร้าง [โปรไฟล์เดี่ยว](../examples/swp1-pw2-v5.yaml) ในไดเรกทอรีส่วนตัวใหม่ รันคำสั่งจากรากของรีโพซิทอรี คัดลอกเฉพาะโปรไฟล์นี้ ไม่ใช่ฐานทั่วไปหรือแพ็กเกจ XS-SSA01:

```sh
SWP_REPO="$PWD"
SWP_BUILD_DIR="$HOME/.local/share/esphome/swp1-private"
umask 077
mkdir -p "$SWP_BUILD_DIR"
cp "$SWP_REPO/examples/swp1-pw2-v5.yaml" "$SWP_BUILD_DIR/"
python3.12 -m venv "$SWP_BUILD_DIR/.venv"
"$SWP_BUILD_DIR/.venv/bin/python" -m pip install 'esphome==2026.9.1'
"$SWP_BUILD_DIR/.venv/bin/python" "$SWP_REPO/scripts/create-secrets.py" \
  "$SWP_BUILD_DIR/secrets.yaml"
"$SWP_BUILD_DIR/.venv/bin/python" -m esphome compile \
  "$SWP_BUILD_DIR/swp1-pw2-v5.yaml"
```

ตัวช่วยจะขอข้อมูลรับรอง Wi-Fi สร้างกุญแจแยกกัน และปฏิเสธการเขียนทับความลับที่มีอยู่ คำสั่งเหล่านี้คอมไพล์โดยไม่เขียนแฟลช ดู [หมายเหตุการจัดเตรียมแบบเข้ารหัส](security-profile.md) ตัวอย่างนี้ใช้ **ESPHome 2026.9.1**, `esp_wroom_02`, **2 MiB, DOUT, 40 MHz** อิมเมจที่ติดตั้งมี **429,600 ไบต์** เขียนที่ `0x0` ด้วย 115200 baud และ esptool ยืนยันแฮชที่เขียน การสร้างครั้งอื่นอาจมีขนาดต่างกัน ตัวเลขนี้เป็นสิ่งที่สังเกตได้ ไม่ใช่ข้อกำหนดการติดตั้ง

## บูตปกติและตรวจรับ

ปิดไฟ ถอด GPIO0–GND และสายสัญญาณ UART ทั้งสองเส้น แล้วจ่ายเฉพาะ 3.3 V ภายนอกอีกครั้ง API เนทีฟที่เข้ารหัสเชื่อมต่อได้ ON/OFF ทำงาน และการรีสตาร์ตซอฟต์แวร์จาก ON คืนสถานะเป็น OFF เจ้าของยืนยันการกดปุ่มสองครั้งพร้อมเสียงรีเลย์และไฟที่เปลี่ยนตาม

จากนั้นถอดสายชั่วคราวและไฟภายนอกทั้งหมด ประกอบตัวเรือนก่อนติดตั้งใช้งานปกติ เจ้าของยืนยันว่าเต้ารับที่ติดตั้งทำงาน **ไม่ได้ทดสอบตัดและจ่ายไฟบ้านแบบควบคุมจากสถานะ ON ไม่ได้วัดแรงดันหน้าสัมผัส หรือวัดทรานเซียนต์ขณะบูต** เสียงคลิกบนโต๊ะเพียงอย่างเดียวไม่พิสูจน์การตัดต่อโหลด

Home Assistant ได้รีเลย์หนึ่งตัวพร้อมการวินิจฉัยการเชื่อมต่อ สัญญาณ เวอร์ชัน และรีสตาร์ต เปลี่ยนชื่อบทบาทที่ติดตั้งใน HA โดยไม่แฟลชใหม่ ชื่อโฮสต์เดิมของเฟิร์มแวร์ยังใช้ได้ เก็บซอร์สส่วนตัวครบชุดทั้งในโฟลเดอร์ ESPHome ของ HA และ ESPHome Dashboard เพิ่มรีเลย์เพียงครั้งเดียวในส่วน Living Room ของแดชบอร์ดหน้าที่สอง การปรับใช้จากรีโพซิทอรีในอนาคตต้องรักษาตัวตนในรีจิสทรีเหล่านี้หรือย้ายอย่างชัดเจน

## หากขั้นตอนล้มเหลว

- **ไม่มีคำตอบอนุกรม:** ตรวจ VCC ขณะมีโหลด กราวด์ร่วม TX อะแดปเตอร์ → RX โมดูล TX โมดูล → RX อะแดปเตอร์ และไม่มีเทอร์มินัลอื่นจับพอร์ต
- **ไบต์อ่านไม่ออก:** จับการรีเซ็ตใหม่ที่ 74880 baud สำหรับบันทึก ROM แล้วใช้ความเร็ว esptool ที่เลือกสำหรับการส่งจริง
- **ยังอยู่โหมดดาวน์โหลด:** ถอดจัมเปอร์ GPIO0–กราวด์แล้วรีสตาร์ต
- **ไฟสถานะติดระหว่างรีเซ็ต:** GPIO0 ขับ LED นี้ด้วย จัมเปอร์บูตที่ต่อกราวด์อาจเป็นสาเหตุ อย่าใช้เป็นการทดสอบรีเซ็ต
- **ปุ่มไม่ทำงานเมื่อต่อเครื่องโปรแกรม:** ถอด UART เพราะ GPIO3 ใช้ร่วมกัน
- **API ทำงานแต่โหลดไม่ทำงาน:** สถานะรีเลย์ที่รายงานไม่ได้วินิจฉัยหน้าสัมผัส ไฟคอยล์ หรือสายไฟบ้าน ห้ามใช้โพรบวัดบนบอร์ดเปลือยที่ต่อไฟบ้าน
